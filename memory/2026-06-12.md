## 17:00-17:50 - PCAAT00 Daily to Hchen 大规模超时事件

### 问题
PCAAT00 cron job（获取 Dubai Assessment $83.18/bbl，每天 17:00-20:50 每 10 分钟运行）连续 7 次 isolated agent 超时（"turn-accepted" phase timeout）。

### 根因
OpenClaw 的 `sessionTarget: "isolated"` cron 机制，脚本输出到 WhatsApp delivery 必须经过 agent 模型中转：
1. cron 启动 isolated agent session
2. agent 运行脚本（<5s 完成 ✅）
3. **agent 需要用模型生成回复**，把脚本 stdout 作为最终回复
4. 模型排队/启动慢 → 超时 → delivery 失败

之前用 gpt-5.5 时 14s 就跑完。今天 deepseek-v4-flash 模型 + 120s 超时不够。

### 关键教训（Tianshu 指出）
**整个架构设计错误** — "拿个价格数据还要经过模型中转" 是画蛇添足。脚本拿到数据应该直接发到 WhatsApp，不需要一个模型在中间做"回声"。

### 修复
1. **脚本重写**：去掉"已送达标记"（lastDeliveredDate），改用数据版本号（modDate）去重。如果 agent 超时，下次重新发
2. **模型指定**：`openai-codex/gpt-5.5`（已被验证最快）
3. **超时**：300s（120s 不够，600s 浪费）
4. **wakeMode**：从 `"now"` 改为 `"next-heartbeat"`（避免 cron 高峰排队）
5. **新增失败通知**：delivery 到 Tianshu（原 job 没通知）
6. **旧 job 已禁用**（id: dd61f441），新建 job（name: "PCAAT00 Daily Dubai Assessment to Hchen (v2)"）
7. **固定 payload** 写入精确的 `cron run` 命令和完整脚本路径

OpenClaw 没有"直接运行脚本 + 输出送 WhatsApp"的 cron 模式。所有 cron 脚本执行都必须经过 isolated agent（含模型推理）。这是一个架构层面的限制，暂无绕过方案。
